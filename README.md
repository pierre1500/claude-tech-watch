## 🧭 Strategic Insights

- 💎 **On SGLang CVE-2026-7301/7302/7304 (3 unpatched CVSS 9.8 RCEs)**: Any organization running SGLang in multimodal mode should treat CVE-2026-7301 as equivalent to CVE-2026-45829 (ChromaDB pre-auth RCE) — the ZMQ ROUTER socket is an unauthenticated shell on your GPU cluster. Immediate actions: (1) restrict `--host` to a trusted internal IP at startup, (2) firewall the ZMQ ports assigned dynamically per inference server, (3) block `/v1/images/edits` and `/v1/videos` at the reverse proxy if not needed, (4) disable `--enable-custom-logit-processor` for CVE-2026-7304. If SGLang is internet-accessible or accessible from a shared corporate LAN, treat the instance as compromised and rotate all credentials accessible from the serving process — GPU cluster service accounts, HuggingFace tokens, model registry credentials
- 💎 **On TeamPCP and AI developer supply chain hygiene**: The TeamPCP campaign has established a playbook that is now publicly available (Shai-Hulud worm source published to GitHub with copycat forks already running). The three structural controls that would have broken the chain at each wave: (1) npm staged publishing (now GA) — stolen OIDC tokens can stage but not approve publish; (2) minimumReleaseAge in pnpm/npm/yarn — a 24-hour wait before installing newly published versions would have caught every poisoned wave; (3) SBOM + dependency scanning with attestation (Chainguard Factory, GitLab 19.0 Dependency Scanning) — catching unsigned packages before installation. All three are now available and free; implement them before the next wave
- 💎 **On MCP 2026-07-28 RC and enterprise deployment planning**: The 10-week window before the July 28 final release is the planning window for teams building MCP-dependent infrastructure. Key decisions: (1) migrate new MCP servers to Streamable HTTP now — HTTP+SSE is deprecated and will eventually be removed; (2) evaluate the Tasks extension for any tool that currently uses polling to track long-running operations — Tasks provides a standard handle-based async operation model; (3) review authorization model against the OAuth/OIDC alignment changes — server-initiated requests now require active client request context, which closes the "prompt out of nowhere" attack surface but requires re-architecting any agent that uses server-push notifications
- 💎 **On AMD EPYC Venice and AMD EPYC Verano for 2026/2027 AI infrastructure planning**: Venice (256 Zen 6 cores, 1.6 TB/s, 2nm) in production ramp with Intel counter delayed means AMD has uncontested server CPU pricing power through 2026; the dual-track strategy (Venice for peak density/training nodes, Verano for hyperscaler efficiency/inference nodes) directly addresses the two dominant AI infrastructure cost structures; organizations planning 2026/2027 server refresh should model Venice as the new baseline for AI training nodes and evaluate Verano against AMD EPYC Turin for inference node TCO
