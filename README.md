## 🧭 Strategic Insights

- 💎 **On the three-CVE kill chain: assume compromise, not patch-and-wait** — CVE-2026-42945 (NGINX Rift) has no known active exploitation yet, but Copy Fail and Dirty Frag do; the chain requires no authentication, produces no disk forensic artifacts, and covers 40%+ of web infrastructure via the WordPress/LEMP nginx config pattern; do not treat these as three separate remediation tickets — treat them as a single incident requiring emergency response: (1) patch nginx to 1.30.1 or apply the named-capture workaround; (2) patch or disable algif_aead + esp4/esp6/rxrpc; (3) assume any system not yet patched may already be compromised and run forensics against memory, not just disk
- 💎 **On AI-generated exploits: SAST is not a defense against semantic logic bugs** — the GTIG zero-day was a trust-assumption hardcode — a class of bug where the code does exactly what the developer intended, but the intent was wrong; this class is invisible to SAST, DAST, and fuzzing; the defensible response is to add LLM-assisted code review specifically for authentication and authorization code paths, and to treat any authentication bypass vulnerability as potentially AI-discovered (and therefore rapidly weaponizable)
- 💎 **On inference infrastructure: route by KV cache state, not by load** — the GKE Inference Gateway production results (35% TTFT improvement, 2x cache hit rate from routing alone) make the case definitively: LLM inference requests should be routed to the pod that already holds the relevant KV cache prefix, not to the least-loaded pod; teams not implementing prefix-aware routing are overpaying for compute and delivering worse latency simultaneously; llm-d's Kubernetes-native KV-aware routing is now production-ready on AWS
- 💎 **On agentic AI governance: build the orchestration layer before the workflows** — the five enterprise requirements (execution-mode governance, logic-step ownership, bounded agent pools, tool-level audit, catalog+gateway composition) are not features to add later; retrofitting governance onto agentic workflows after the first incident is structurally harder than designing for it from day one; AWS Agent Toolkit's IAM guardrails + CloudTrail model is the reference implementation of what "governed agentic operations" looks like in practice
