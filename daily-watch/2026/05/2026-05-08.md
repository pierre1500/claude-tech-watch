## Major Signals

### 1. LLM Inference Disaggregation Is Crossing the Datacenter Boundary

**What happened:** A wave of production-grade research and tooling has pushed prefill/decode disaggregation beyond single-cluster RDMA domains. PrfaaS (Prefill-as-a-Service) from an internal 1T-parameter hybrid model deployment demonstrates that by combining hybrid-attention architectures (which reduce KV cache size) with bandwidth-aware scheduling and cache-aware routing, long-context prefill can be offloaded to standalone compute-dense clusters over commodity Ethernet — no shared RDMA fabric required. Result: 54% higher serving throughput vs. homogeneous PD and 32% vs. naive heterogeneous baselines.

**Why it matters:** The previous constraint was tight coupling between prefill and decode via InfiniBand/RDMA for KV cache transfer. Hybrid-attention models and smarter routing break that constraint. This enables independently scaling prefill capacity (compute-bound) and decode capacity (memory-bandwidth-bound) across geographically distributed clusters — a fundamental shift in inference economics at hyperscale.

**Architectural impact:** Inference stacks are converging on a 3-tier model: (1) Pre-prefill nodes for cold/long-context requests writing KV to distributed cache, (2) Prefill nodes prioritizing warm/cached requests via RDMA read, (3) Decode nodes fully isolated for latency-sensitive token generation. NVIDIA Dynamo 1.0 (open-source) materializes this as a production-grade orchestration layer above SGLang/TensorRT-LLM/vLLM, shipping KV-aware routing with 170M ops/s Flash Indexer throughput.

**Strategic implications:** Infrastructure teams building internal inference platforms must rethink resource planning. GPU procurement strategies that treated all inference hardware as interchangeable are now suboptimal — the right architecture separates compute-optimized (prefill) from memory-bandwidth-optimized (decode) GPU pools with active routing intelligence between them.

SLSA Level 3 (tamper-resistant build environment + cryptographically signed provenance attestations) is rapidly becoming a requirement, not a best practice, for regulated and federal environments.

### 3. WASM-eBPF Convergence: The Kernel Is Being Unbundled

**What happened:** The bpftime userspace eBPF runtime, combined with WASM-to-eBPF transpilation pipelines, is enabling developers to write kernel-level logic in Rust/Go/C++ compiled to WASM, then JIT-translated into eBPF bytecode. Production deployments show context-switch latency reductions from 1.2ms to under 150ns for observability and security filtering workloads at the NIC level. WASI profiles for kernel-level interoperability are actively being specified for H2 2026.

**Why it matters:** This breaks the historical binary between safe (user-space, slow) and performant (kernel module, risky). eBPF's verifier provides safety guarantees; WASM provides language-agnostic developer ergonomics; JIT provides near-native performance. Security logic (DPI, fine-grained ACLs) can now be embedded directly in the data plane at near-zero overhead.

**Future evolution:** Expect WASM modules managing NVMe storage controllers and 5G/6G signal processing directly in kernel space within 18 months. The Kubernetes runtime layer is already adapting: orthogonal runtimes (heavy stateful services in OCI containers + stateless filters in WASM) with eBPF for targeted observability is the 2026 platform engineering pattern.

## AI Engineering

### Inference Stack Consolidation: Three Engines, One Orchestration Layer

In 2026, three inference engines dominate production LLM serving: TensorRT-LLM (2,780 tok/s, 28 min cold start, best for peak throughput), SGLang (2,460 tok/s, ~58s cold start, optimal for shared-prefix workloads like RAG/chatbots), and vLLM (2,400 tok/s, ~62s cold start, fastest path to production, broad model support). NVIDIA Dynamo sits above these as the coordination layer, adding KV-aware routing, disaggregated serving, SLA-driven autoscaling, and multi-tier KV cache offload (GPU → CPU → SSD → remote storage).

**Speculative decoding in 2026:** Draft models (1-7B parameters) generate 3-12 candidate tokens; the target model verifies all in a single parallel forward pass. Acceptance rate 70-90% on domain-specific tasks yields 2-3x speedups with mathematically identical output quality. Critical production caveat: speedup degrades at high batch sizes — match technique to workload before committing.

**Cache hit rates for agentic inference:** Claude Code achieves 85-97% KV cache hit rates on subsequent turns, with agent teams achieving 97.2% aggregate hit rates across 4-agent teams. The write-once-read-many (WORM) access pattern of agentic workloads (11.7x read/write ratio) creates entirely different infrastructure optimization targets than traditional chatbot serving.

**Cloudflare's Unweight:** LLM weight compression at 15-22% without accuracy loss, reducing GPU memory pressure and inference latency. Signals that weight compression is becoming a first-class infrastructure concern alongside quantization.

## Distributed Backend

### Kubernetes 1.36: DRA Matures, Pod-Level Resource Managers Land

**Dynamic Resource Allocation (DRA) in stable/beta:** Hardware heterogeneity support via prioritized device lists with fallback preferences (e.g., request H100, fallback to A100). Extended resource support bridges legacy systems to DRA for gradual migration. Partitionable devices (beta) for fine-grained GPU sharing.

**Pod-Level Resource Managers (alpha):** Enables hybrid resource allocation — NUMA-aligned exclusive CPUs for ML containers + shared pool for sidecars, without forcing all containers in a pod to hold exclusive resources. This eliminates a painful trade-off for GPU-accelerated workloads running alongside service mesh sidecars.

**Gang scheduling via Workload API:** All-or-nothing scheduling for distributed training, Spark, and Ray pipelines — critical for preventing partial allocation deadlocks in large-scale AI/ML workloads.

**Figma FigCache case study:** Figma built an in-house Redis proxy with RESP protocol compatibility and swappable backends (AWS MemoryDB, Postgres) targeting six-nines uptime. Motivated by Redis licensing uncertainty (AGPL v3 return in May 2025 after the SSPL controversy). Architectural lesson: abstract cache backends behind a protocol layer to retain operational flexibility.

**Cell architecture for blast radius reduction:** The production pattern for 2026-scale distributed systems — routing customers to mostly self-contained slices (compute + cache + queues + regional DB). Cell degradation reroutes affected slices only, not entire customer base. Pairs with sidecarless/ambient service mesh (centralized policy + identity, reduced per-workload overhead) and QUIC/HTTP/3 for transport.

**SWARM+ research:** Hierarchical PBFT consensus for distributed workload management reduces coordination complexity from O(n²) to O(log n) via tree-structured agent groups. Adaptive quorum mechanism allows consensus progress under reduced agent capacity without explicit membership reconfiguration. Directly applicable to planetary-scale multi-agent scheduling systems.

## Data Engineering

### DuckLake 1.0: SQL Database as Lakehouse Metadata Catalog

**What happened:** DuckDB Labs shipped DuckLake 1.0 (April 13, 2026), the first stable release of a lakehouse format that stores metadata in a standard SQL database (PostgreSQL, SQLite, or DuckDB) while keeping data in open Parquet files. Benchmarks show 926× faster queries and 105× faster ingestion versus Apache Iceberg.

**Why it matters:** Traditional open table formats (Iceberg, Delta Lake) store metadata as files in object storage, creating compaction overhead, catalog complexity, and inefficiency for small writes (a single-row addition requires writing a new Parquet file + updating manifests + updating catalog). DuckLake buffers small changes in the metadata database and flushes to Parquet at economically efficient batch sizes.

**Current lakehouse landscape (2026 state):**
- **Apache Iceberg:** Won as the cross-platform open table format for multi-engine environments (Spark, Trino, DuckDB, Flink, Snowflake). V4 spec work: efficient column updates for wide ML tables (write only changed columns, stitch at read time) — targeting petabyte-scale feature stores with thousands of embedding columns
- **Delta Lake:** Path of least resistance inside Databricks/Unity Catalog ecosystem
- **DuckLake:** The simplification bet — evaluating if Iceberg catalog complexity is a blocker
- **Apache Paimon:** Streaming-first lakehouse for high-frequency upsert workloads
- **MinIO OSS:** Archived February 2026 — migrate to SeaweedFS for self-hosted S3-compatible storage

**Spotify case study:** Background AI agents migrating 1,800 data pipelines. Signals the maturation of AI-assisted data infrastructure work beyond prototyping.

**Foundational 2026 streaming pattern:** `Operational DB → CDC → Streaming Layer → Iceberg Sink → Data Lake → Query Engine`. Iceberg as the universal interface at the center of modern data platforms.

## Realtime Systems

### WebTransport Reaches Production: The QUIC-Native Upgrade Path

Safari 26.4 shipped WebTransport support, completing major browser coverage (Chrome 97+, Edge 98+, Firefox 114+, Safari 26.4+). This closes the last major browser gap that kept WebTransport experimental.

**Architecture decision in 2026:** WebSockets remain the safest default for universal reach. WebTransport enables HTTP/3, QUIC multiplexed streams, and unreliable datagrams — the right choice for live state sync, collaboration cursors, telemetry, and interactive media control. Production pattern: prefer WebTransport with WebSocket fallback for progressive enhancement.

**WebTransport advantages over WebSocket:**
- No head-of-line blocking (slow stream never blocks others on lossy links)
- Unreliable datagrams (UDP-style, sub-50ms latency for cursors/gaming)
- Multiple ordered reliable streams per connection
- QUIC connection migration (session survives IP change)

**Media over QUIC Transport (MoQT):** Approaching RFC status (2026 target per IETF MoQ WG). OpenMoQ consortium launched, including Akamai, Cloudflare, and Google. Alibaba has completed A/B testing in commercial production. CDN ecosystems adopting MoQT CDN capabilities (Cloudflare MoQ CDN now available). The IETF-standard replacement for WebRTC in large-scale media delivery.

**Local-first architecture gaining momentum:** Architectural shift from request-response to sync-engine. CRDTs (Automerge, Yjs) for concurrent edit handling without merge conflicts. ElectricSQL, Replicache for local-first databases with background sync. WebRTC + WebTransport for P2P sync to reduce server costs. Zero latency (local CPU speed) + offline resilience + E2E encryption by design.

### Agentic Infrastructure Becomes Its Own Budget Category

AWS Bedrock AgentCore, Google Gemini Enterprise Agent Platform, and Azure Agent Factory represent the hyperscaler formalization of agentic infrastructure as a product category distinct from LLM serving or MLOps.

**The core architectural distinction:**

| Dimension | LLM Serving | Agentic Infrastructure |
|-----------|-------------|----------------------|
| Execution model | Single request/response | Iterative loops with tool calls |
| State | Stateless | Stateful sessions, persistent memory |
| Lifecycle unit | Request | Agent session / task |
| Task duration | Milliseconds–seconds | Minutes–hours |

**Coordination failures are the primary failure mode:** Research across AutoGen, CrewAI, and LangGraph finds coordination failures account for 36.94% of all multi-agent system failures. Multi-agent systems consume ~15x more tokens than chat interactions (Anthropic data). This frames orchestration as a cost-amplification layer — the architecture must justify the overhead.

**Emerging pattern — hierarchical consensus for agent scheduling:** SWARM+ demonstrates that O(n²) flat-mesh agent coordination can be restructured to O(log n) via hierarchical tree-structured groups with adaptive PBFT quorum. Critical for large-scale agent fleets where flat coordination becomes the bottleneck.

**MCP as infrastructure standard:** Anthropic donated MCP to the Linux Foundation (now under Agentic AI Foundation) with co-founders Block and OpenAI, backed by Google, Microsoft, AWS, Cloudflare. MCP is becoming the default integration layer for agentic AI — the "USB-C for AI tools." Gartner predicts 40% of enterprise applications will feature task-specific AI agents by end of 2026, up from <5% in 2025.

**Production multi-agent patterns:**
1. **Coordinator-Specialist:** Triage agent detects intent → routes to specialized agents with isolated context + optimized toolsets
2. **Handoff chains** (OpenAI Agents SDK): Explicit context-carrying agent-to-agent transfer
3. **GroupChat** (AG2/AutoGen): Event-driven multi-agent conversation with selector orchestration
4. **Declarative graphs** (LangGraph, AWS Strands): Hard-coded business rules + flexible AI reasoning in hybrid graphs
5. **Human-in-the-loop:** Planning layer user review before execution — essential for enterprise workflow variance

## Emerging Trends

### 1. The Inference Stack Becomes Infrastructure Platform
The separation of inference concerns (routing, scheduling, caching, disaggregation) from model serving is creating a distinct infrastructure layer analogous to what Kubernetes did for containerized compute. NVIDIA Dynamo, vLLM, SGLang, and custom implementations at hyperscalers are converging on the same architectural primitives: KV-aware routing, disaggregated prefill/decode, multi-tier caching, and SLA-driven autoscaling.

### 2. Autonomous Offensive Security Is Here
The Zero Day Clock collapsing to sub-1-day exploitation, XBOW topping HackerOne, DARPA AIxCC finding 54 vulnerabilities in 4 compute hours — these are not theoretical warnings. Autonomous vulnerability discovery and exploitation is operational in 2026. The asymmetry is stark: defenders still operate on human timescales; attackers have weaponized ML. Continuous exposure management (not periodic scanning) is the minimum viable posture.

### 3. WASM as Universal Runtime Primitive
The convergence of WASM in the kernel (eBPF transpilation), WASM at the edge (Cloudflare Workers, Fastly Compute), WASM for distributed consensus (WASI 0.2 Raft), and WASM for agent tool sandboxing (Orloj's WASM tool integration) signals a fundamental shift. WASM is becoming the lowest-common-denominator safe execution primitive across all compute tiers.

### 4. Data Infrastructure Bifurcation
Two parallel movements: (1) DuckLake's simplification thesis — SQL database as metadata catalog, eliminating Iceberg's operational complexity; (2) Iceberg V4's expansion thesis — native support for ML-scale wide tables and efficient column updates. The market will likely segment: DuckLake for organizations where catalog complexity is the bottleneck; Iceberg for multi-engine, multi-cloud, petabyte-scale deployments.

### 5. AI-Native Development Security Lag
Organizations are deploying AI coding agents at scale while SLSA, SBOM, and supply chain attestation frameworks have not yet been updated to handle non-human code authors. The security gap between agentic deployment velocity and governance maturity is widening. 2026 will see the first significant incidents from AI-generated code with compromised or ambiguous provenance chains.

## Strategic Insights

**On inference economics:** Teams building internal AI platforms in 2026 must separate the capital planning question (which GPU types, how many, for what phases) from the software architecture question (routing, scheduling, disaggregation). Treating all inference GPUs as interchangeable will lead to 2-3x cost inefficiency compared to architectures that distinguish prefill (compute-bound, benefit from high-FLOP chips) from decode (memory-bandwidth-bound, benefit from high-HBM chips).

**On supply chain security:** The four supply chain compromises in four months (eScan, Notepad++, CPU-Z, DAEMON Tools) represent a shift in attacker strategy from exploiting individual vulnerabilities to exploiting the distribution and trust infrastructure itself. SLSA Level 3 as a baseline (not a gold standard), VEX for exploitability context, and build-time cryptographic provenance are the minimum architectural responses.

**On agentic infrastructure:** The most important architectural decision for organizations deploying AI agents is not which framework to use — it is where to place the coordination boundary. Single-agent with a concatenated toolbox handles most tasks that fit in one context window. Multi-agent orchestration is technically justified when privilege boundaries exist between agents or when multiple stakeholders are represented. Building multi-agent systems prematurely multiplies cost and coordination failure surface for no gain.

**On the eBPF+WASM convergence:** Platform engineering teams should begin piloting orthogonal runtimes now — not for the performance gains (which are real) but for the architecture muscles. The skill set required to reason across kernel eBPF hooks, WASM execution contexts, and container runtimes is becoming a core platform engineering competency. Teams that develop it now will be 12-18 months ahead when WASI kernel profiles stabilize.

**On cloud concentration risk:** With $500B+ in annual cloud infrastructure spending projected for 2026, the Big Three (AWS/Azure/GCP) capture 60%+ of a market growing at 35% YoY. The strategic risk for large engineering organizations is not cloud cost but lock-in depth — as each hyperscaler builds proprietary AI infrastructure services (Bedrock AgentCore, Gemini Enterprise Agent Platform), vendor gravity intensifies. Google Spanner Omni and cross-cloud Iceberg federation signal the multi-cloud architecture as a realistic defensive strategy.
